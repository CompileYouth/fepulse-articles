开头先展示 Moritz 的系统：他搭了一个 Claude OS，本质上是一组 skills 和小自动化的集合。每次增加新工具、新 MCP 或 CLI，他就让系统把它写进 `tools.md`。系统还会在夜间做“dreaming”：检查 daily memory files，把它们压缩进 long-term memory file。它也能把上周买过的商品重新加入购物车，帮助自动化 grocery shopping。Moritz 说，关键是先搭好初始结构，然后一个工具一个工具地接上去。

主持人说，现在大家都有一个“第一世界难题”：应该在 OpenClaw 还是 Claude Code 里搭自己的 personal chief of staff？因此请 Moritz 来比较两个系统的优劣，并展示他怎样把 Claude Code 设置成自己的 chief of staff，从 folder structure 到 skills。

## OpenClaw 和 Claude Code 的取舍

Moritz 先用一张图比较 OpenClaw 和 Claude Code。他认为 OpenClaw 的第一个优点仍然是 mobile access。OpenClaw 从一开始就可以带进 Telegram、Discord、Slack 等聊天应用，这是它最突出的特性之一，也解释了为什么它那么受欢迎。相比之下，Claude Code 后来有 dispatch，也有 Telegram 和 Discord 插件，但使用体验仍不如 OpenClaw 在聊天应用里的原生体验。

主持人同意，说 OpenClaw 像是在 Telegram 里和朋友聊天，而 Claude Code dispatch 和 channels 更像 coding-first interface，不太像给朋友发短信。

第二个 OpenClaw 优点是 heartbeat。Heartbeat 让 OpenClaw 更像一个 always-on 的东西。默认每 30 分钟触发一次，OpenClaw 会醒来，执行 `heartbeat.md` 里指定的任务。Claude Code 过去几个月做了一些类似能力，比如 loops，但场景不同，而且只能持续三天，不能完全替代 heartbeat。

主持人问 Moritz 的 heartbeat 里放什么。Moritz 说，他尝试过很多东西，最重要的是改善 memory。早期 OpenClaw 的 memory 很差，所以他让 heartbeat 不断检查 sessions，把自己在做的事情保存进 daily memory。他还用 heartbeat 管理 to-do list：检查自己在做什么，自动在 to-do list 里打勾，减少手动维护。

第三个 OpenClaw 优点是 cron jobs。OpenClaw 更像应该放在云端或另一台机器上的东西，所以创建 cron jobs 更自然。Claude Code 也有 schedule，后来改名 routines，但有本地版本和 cloud hosted 版本，使用起来更复杂。不过主持人补充说，Claude Code app 里可以看到 routines 列表，这一点比 OpenClaw 更清楚；OpenClaw 里要知道自己有哪些 cron jobs，还得去问 agent 或看 dashboard、cron 文件。

第四个优点是 sub agents。OpenClaw 可以比较容易创建 sub agent，让主 agent 与其交互。Claude Code 目前没有完全对应的消费者体验，虽然可以用 Paperclip 等工具绕一下，也有 Claude managed agents，但那更偏开发者。

Moritz 也说，很多人其实不需要 sub agents。大多数 OpenClaw 用户只需要一个主 agent，再通过 Telegram group 或不同话题讨论即可。Sub agents 真正有价值的时候，是需要隔离上下文，比如每个 business 一个 agent。否则管理多个 sub agents 的 context 也会很复杂。他自己会用另一个 agent 做内容 review，避免 reviewer 被“我刚刚起草了这个内容”这个上下文影响。

## Claude Code 的优势：可靠、模型强、权限更清楚

转到 Claude Code 的优点，Moritz 认为目前最大优势是 reliability。OpenClaw 仍然会随机坏掉：更新后坏、模型突然不工作、整体还很 techy。Claude Code 虽然也会有 downtime，但总体更像稳定工具。

另一个优势是模型。Anthropic 切断 OpenClaw 对某些 Claude 能力的访问后，很多人转向 Claude Code。Moritz 说，很多人认为 OpenClaw 体验好，是因为背后用了 Opus 模型。主持人提到自己试过 GPT-5.4 配 OpenClaw，体验很差，因此也更多转向 Claude Code。

Claude Code 还更安全一些，虽然安全往往表现为频繁要求用户批准操作，这有时也很烦。Moritz 说，他有时会开启 bypass permission mode，让体验更流畅，但这样安全性也会降低。

主持人说，他们两人都在两个系统上搭过东西，比较系统本身有点像假工作。目前他把 email、calendar、Google Docs 等事务管理仍放在 OpenClaw，而构建类任务主要用 Claude Code 或 Codex。Moritz 也有类似感觉：OpenClaw 更像一个潜在更 autonomous 的员工，应该放在云端或另一台机器上；Claude Code 则更像自己主力电脑上的工具，增强自己的工作。

Moritz 说，因为 OpenClaw 不可靠，他尝试在 Claude Code 里重建一套 OpenClaw 系统，也就是自己的 Claude OS。

## Claude OS 的几个实际例子

正式讲架构前，Moritz 先展示例子。他在 Claude Code desktop app 里输入一个 prompt：从某个 Instagram video 获取 transcript，按照自己的 offer 写两个类似 scripts，并把它们保存为 Google Drive 里名为 Claude content system 的文件。

这个流程使用了一个叫 talk script 的 MCP tool 来获取视频 transcript，然后用 Claude Code 智能写 scripts，再用另一个工具访问 Google Drive 并创建文件。Moritz 说，Google Workspace CLI 可能是他现在最强大的工具，因为它让系统能访问 Google Drive 并执行很多操作。

主持人说，他不太相信只用本地 markdown 和 Obsidian 管理一切，更喜欢东西还在 Google Drive 里，因为在云端、手机也能用。Moritz 同意，说自己也试过本地系统，但如果所有东西都只在本机上，访问起来不方便。

另一个例子是：找出自己过去用过的所有 APIs，整理到 Google Sheet，并上传到 Drive。Claude OS 会搜索本地文件系统里保存的 memories，把最近提到或研究过的 API 提取出来，创建 Google Sheet 上传。Moritz 的 memory 系统目前还很简单，模仿 OpenClaw：有一个 `memory.md`，还有一个 memory folder，里面是 daily memory files。以后如果文件很多、很大，可能会用更复杂的 QMD。

## folder structure：cloud.md、memory、tools.md

Moritz 的 Claude OS 叫 Claudia。UI 层主要是 Claude Code desktop app。他说这个 app 大概出来十天，但已经比 terminal 体验好很多，可以侧边打开文件、查看 plan 等。只有少数缺失功能时，他才用 terminal。如果进入文档编辑模式，他会用 Cursor 或 VS Code 加 Claude Code extension，因为这样可以高亮文档片段、让 AI 修改。

文件结构里最重要的是 `claude.md`。它类似 OpenClaw 里的 `agents.md`，是每次 session 首先读取的 master instruction，像 system prompt。`claude.md` 会写明“你是 Claudia，这是你的 workspace”，并引用其他文件。

其中有 memory loop：每次交互后保存一行到 daily memory，必要时保存 long-term memory。这样每个对话都会逐渐积累记忆。还有 identity / soul 文件，定义 personality；`user.md` 存放关于 Moritz 本人的信息；business context 放在各自文件夹里。

Moritz 特别强调 `tools.md` 很重要。每当他添加一个新工具、新 MCP 或 CLI，就让系统把它写进 `tools.md`。这样 Claude OS 知道自己有哪些工具可用。Memory 系统则包括 daily memory 和 long-term memory。夜间 routine 会做 dreaming：检查 daily memory files，把内容压缩进 long-term memory file。Moritz 现在让 memory 只写一两行，所以暂时没有过长，但未来可能需要更好的 memory system。

Secrets 则放在 `.env`。主持人问怎样把 secret 分享给 Claude。Moritz 说他不会把 secret 直接贴进 chat，而是自己打开 `.env` 文件写进去。他也在考虑用 1Password，为 agents 创建单独 vault，让 Claude OS 访问那个 vault。

## tools、skills、routines 和自动化

Moritz 说，工具层最重要。工具有几类：CLI、MCP、API。Claude Code 能使用本机 CLI，是它相比一些 sandboxed 工具的优势。MCP 的接入方式现在有点混乱：可以从 desktop app 连接，也可以在 CLI 里连接，但总之可以让 Claude Code 使用它们。主持人担心 MCP 会撑爆 context，Moritz 说最近改善后影响没有那么大。

他现在选择软件工具时，会先看它有没有 CLI，再看有没有 MCP，至少也要有 API。如果都没有，他会倾向找另一个工具。

还有 skills 层。Moritz 为自己的工作流创建了很多 skills。只要一个 workflow 重复执行几次，他就会让 Claude Code 把它变成 skill，以后复用。

一个例子是 grocery skill。它会使用 browser，登录购物应用，先把上周买过的商品重新加入购物车，再根据他聊天里新增的清单搜索商品并加入购物车，最后让他确认。这就自动化了日常买菜。

另一个例子是 video upload workflow。以前他给剪辑师上传视频时，要去 Google Drive 创建文件夹、拖文件、复制链接、分享给编辑。现在只要说运行 video upload workflow，它会创建正确的文件夹，并根据脚本内容生成文件夹名。Moritz 只需要把手机里的文件上传进去。

Routines 是 Claude Code 的新自动化功能，有 local 和 remote 两种。Local routine 需要 desktop app 开着，电脑也要开着，会在本机运行，因此能使用本机 CLI 和所有本机工具。Remote routine 则适合电脑不在线也要运行的自动化，但要先创建 repo，把 automation 所需内容放进去，托管在 GitHub，让它在云端运行。

Moritz 只有一个 remote routine，叫 YouTube monitor。它会监控指定频道，抓取最新视频的 views、likes、comments，放进 Google Sheet，每周运行一次，用来观察类似频道的视频选题和表现。主持人问是否还有 skill 分析这些数据并给建议。Moritz 说，他有另一个仍在 OpenClaw 上跑的 skill，会把 idea folder 里的想法和手动记录的 ideas 变成 weekly plan。

## content system：从想法到短视频发布

Moritz 说，当基础结构和工具接好后，就可以搭更完整的系统。比如他的 content system，本质上是一组 skills 和小 automations 的组合，用来生产 short form video content。他最初在 OpenClaw 里搭，现在正在迁移到 Claude OS。

他主要通过 Telegram 操作这个系统。Telegram group 里有多个 subtopics。第一步是 idea capture，有几种来源：可以直接在 Telegram 里发一句想法，比如“compare OpenClaw with Claude Code”，系统会把它记录进 idea docs；YouTube monitor 会自动抓取相似频道；他还会在 Twitter 上看到有启发的帖子时，直接 DM 给自己的 OpenClaw bot 账号，再由 automation 读取 DM 并记录。

主持人说，这比 bookmark 更好，因为 bookmarks 常常变成坟场。Moritz 说，他也觉得需要一种方式把 bookmarks 里的东西取出来。

Ideas 捕获之后，进入 weekly planning。系统会汇总所有 ideas，挑一些主题，排成 Monday、Tuesday、Wednesday 等计划，并添加细节。计划批准后，系统会根据过去 scripts 帮他写新 scripts。他已经积累了一个 short form scripts library，每天一个脚本。

Moritz 会 review scripts，并手动补充细节。他不会直接拿 AI 完整写出的 script 去录。更喜欢的方式是让系统先根据 plan 生成 notes；他看 notes，用 Whisper Flow 继续添加自己的点；再用 skill 把 notes 转换成自己常用的 script style。对于一周七条视频，他就反复执行“补 notes、转 script”的循环。

Filming 阶段，他把 script 放到手机上，然后对着手机录。他承认有些人可以只看 bullets 就自然发挥，但他需要看到一些内容。录制本身不花太多时间，script 准备好后，打开手机大约十分钟就能录完。他喜欢这种手机上的自然 UGC 风格，因为过去测试下来，这种风格表现最好。

录完后，视频编辑进入流程。Moritz 的内容一般是他对着镜头说话，有时再录屏展示东西。他会把自己和屏幕素材发给编辑。这里也半自动：运行 video upload workflow，系统根据 script 创建对应文件夹，他从手机上传文件即可。

编辑完成后，会把成片 Drive 链接发回来。Moritz 把链接贴给 agent，agent 使用一个 CLI tool 把视频发布到各个平台。这个工具是 postiz，他用它发布到 YouTube、Instagram 和 TikTok，也能生成 captions。Moritz 提醒，TikTok 通过 API 发布可能影响表现，尤其新账号最好先用人类手动上传 warm up。Instagram 也有一些 creator 圈里的说法，比如通过 Edits app 上传可能表现更好，他试过后觉得也许有效，但很难 A/B test。

他还自动化了 Instagram 常见的“评论领取资源”流程。系统会根据 script 创建一个 Notion resource，放入相关链接，再把这个链接放进 ManyChat automation。这样有人评论索取资源时，也能自动回复。

主持人总结说，真正还手动的部分是创作视频和编辑视频。Moritz 说，对他来说最手动的是 script review，因为要确保质量。录制反而很快，编辑一条短视频大概半小时。他强调，这就是他的 no AI slop flow：AI 不直接替他完整写完，他会加入自己的判断。

## 从一个结构开始，逐个连接工具

主持人说，creator 有大量重复工作，团队又小，所以会处在 AI adoption 前沿。Moritz 同意，并说这个系统还可以扩展到 long form、Twitter repurpose、newsletter 等很多环节。

最后主持人问，如果有人想在 Claude Code 上搭自己的 personal OS，有什么建议。Moritz 说，最重要的是 just get started。先搭初始 folder structure，然后从最占时间的事情开始，一步一步自动化。不需要一次接上所有工具。先接一个工具，然后从那里继续。

Moritz 的核心建议就是：先把基础结构放好，包括 folder structure、记忆、工具说明和技能，然后逐渐把自己的真实工作流接进来。系统不是一开始就完整，而是在每次重复工作里长出来的。

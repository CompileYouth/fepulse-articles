节目开头先剪出 Andre Karpathy 的几句话。他说，现在“写代码”甚至已经不是正确动词了，他每天 16 个小时是在向 agents 表达自己的意志，或者说 manifest。另一个问题不再是有没有 Claude Code、Codex 这类单个 agent harness，而是怎样同时拥有更多 agent，怎样正确使用它们，怎样为它们写 instructions，又怎样优化这些 instructions。LLM 本身已经被默认存在，agent 也开始被默认存在，接下来是多个更持久的自动化实体一起工作。正因为这件事几乎无限展开，任何不顺利都像是 skill issue，所以才让人进入一种“AI psychosis”状态。

主持人介绍说，这期 No Priors 请来 Andre Karpathy，讨论 code agents、工程和 AI research 的未来、更多人怎样参与研究、robotics，以及新一代教育。访谈一开始，主持人提到最近几个月 AI 进展很快，自己曾经走进办公室，看到 Andre 非常沉浸，问他在做什么，他说自己必须每天 16 小时“写代码”，但马上又纠正说，写代码已经不是准确说法。

Andre 说，去年 12 月左右出现了一个巨大解锁。他从原来大约 80% 自己写代码、20% 委托 agent，变成 20% 自己写、80% 交给 agent。现在甚至不止这个比例，他觉得自己从 12 月以来几乎没有亲手敲过一行代码。这对普通人来说很难意识到有多剧烈：如果随便找一个软件工程师，看他桌上的默认工作流，基本上已经和 12 月前不同了。

他现在处在持续探索状态里，想弄清楚什么是可能的，怎样把事情推到极限。问题变成：怎样不只有一个 Claude Code 或 Codex session，而是同时有多个？怎样合理分配？这些“claw-like entities”究竟是什么？Twitter 上很多人都在做看起来很好的新东西，他担心自己不在最前沿，于是不断试探。

## 从写代码变成调度宏动作

主持人问，现在 Andre 的探索能力受什么限制。Andre 说，很多事情如果不工作，他都会感觉是 skill issue，而不是能力本身不存在。也许是 `AGENTS.md` 里的指令写得不够好，也许缺少合适的 memory tool，也许没有把已有能力串起来。

他提到 Peter Steinberger 的工作方式：屏幕上开着很多 Codex agents，每个任务如果用 high effort 和正确 prompt，大约跑 20 分钟。他会在多个仓库和多个 agent 之间切换。人的动作层级因此变大了，不再是一行代码、一个函数，而是“给 agent 1 一个新功能”“给 agent 2 另一个不会冲突的新功能”“让另一个 agent 做 research”“再让一个 agent 写 implementation plan”。整个仓库像是被一组宏动作操纵。

Andre 觉得这种能力非常有回报，因为它真的有效。同时，它也带来新的学习曲线。每当自己在等一个 agent 完成任务时，最自然的想法就是：我还能再做更多工作。如果 token 或订阅额度还没用满，就会感觉自己没有最大化 throughput。这让他想起读博士时，如果 GPU 没跑满，人会焦虑自己浪费了可用 FLOPs。现在焦虑从 FLOPs 变成 token throughput：你能调度多少 token、多少 agent，自己是不是系统里的瓶颈。

主持人说，这种焦虑也说明行业重新有了资源约束。过去十年很多工程任务里，人们并不觉得 compute 是限制；现在能力突然上升后，大家发现限制不再是能不能访问 compute，而是人自己怎样调度它。Andre 说，这正是它上瘾的地方：如果一切都像 skill issue，就意味着你可以变得更好。

## Claw：比一次 session 更持久的自动化实体

主持人问，如果一年后达到某种 mastery，会是什么样。Andre 说，每个人都在往更高层走。单个 agent session 不是终点，多个 agent 怎样协作、怎样组成 team，是大家都在探索的方向。

他把 “claw” 称为另一个有意思的方向。这里的 claw 指一种更持久的 layer。它不是你一直在交互式盯着的 session，而是有自己的 sandbox，能在你不看时持续循环、代表你做事，并且拥有比普通 agent 更复杂的 memory system。OpenClaw 的 memory 比默认的 context compaction 更强。

Andre 认为 Peter 在 OpenClaw 里同时做了很多创新。第一是 personality。很多当前 coding agents 没有把人格调好。Claude 给人的感觉比较像 teammate，会和你一起兴奋；Codex coding agent 则更干，常常只是说“我实现了”，但不像真的理解你在构建什么。Claude 的恭维也调得比较好：当你给它一个并不成形的想法时，它不会过度夸奖；当你自己也觉得是个好想法时，它会更明显地认可。Andre 甚至觉得自己在努力赢得 Claude 的赞赏，这很奇怪，但也说明 personality 对协作体验很重要。

除了 personality，OpenClaw 还有 memory system，以及一个通过 WhatsApp 进入所有自动化的入口。Andre 说，这让 claw 更像一个有持续存在感的协作者，而不是一次性命令执行器。

## 用 claw 接管家庭自动化

主持人问 Andre 有没有把 claw 用在软件工程之外。Andre 说，他在 1 月经历过一段“claw psychosis”，做了一个负责家里事务的 claw，名字叫 Dobby。它通过 WhatsApp 和他对话。

他让 agent 在本地网络里寻找智能家居子系统。Andre 只是告诉它，自己家里应该有 Sonos。Agent 扫描局域网，找到了 Sonos 系统，发现没有密码保护，随后上网搜索 API endpoint，尝试反向理解如何控制它。几条 prompt 后，音乐就从书房响了起来。Andre 对此很惊讶：自己只是问“你能找到我的 Sonos 吗”，最后它就能播放音乐。

同样的方式还被用于灯、HVAC、窗帘、泳池、spa 和安防系统。Dobby 做了 API 和 dashboard，让 Andre 可以看到家中各种设备的控制中心。比如他说 sleepy time，所有灯就会关闭。安防部分则有一个摄像头对着室外，当检测到变化后，会把视频片段交给 Qwen 模型判断。如果 FedEx 车来了，Dobby 就会通过 WhatsApp 发一张图片并提醒他。

Andre 说，过去他要用六个不同 app 控制家里设备，现在自然语言入口统一了这些系统。他还没有把这个模式推到极限，但已经很有启发性。

主持人问，这是否说明未来软件体验会改变。Andre 认为，一定程度上是的。人们心里的“AI”不是原始 LLM 这种 token generator，而是一个有 persona、有身份、能记住事、能被吩咐的实体。WhatsApp 背后的某种存在比“调用模型接口”更符合人的预期。LLM 作为原始 primitive 对多数人来说还不够像 AI，背后需要大量技术细节把它包装成符合人类直觉的 entity。

这也指向一个更大的问题：很多 app 是否本来就不该存在。智能家居设备当然需要硬件，但每个设备都配一个封闭 UX layer，就显得多余。也许它们更应该暴露 API，让 agent 直接调用。Agent 扮演智能胶水，组合不同工具，做单个 app 做不到的复杂自动化。

Andre 还提到跑步机。它也有自己的 app，但他只是想记录自己多久做一次有氧。为什么要登录 web UI、走完整流程？这类能力应该是 API-first，并被 agent 代表人调用。今天普通人还需要 vibe coding 才能做到，但 Andre 认为一年、两年、三年后，这类事情应该变成 table stakes。

## Auto research：把人从循环里移出去

主持人问 Andre 为什么没有继续把 claw 推得更远。Andre 说，一方面自己被太多事情分散注意，另一方面也还不愿把 email、calendar 等数字生活完全交给它，因为安全、隐私和粗糙边缘仍然让他谨慎。

随后话题转向 auto research。Andre 说，他之前发过一个观点：要从当前工具里获得最大价值，就必须把自己从瓶颈位置移开。不能每一步都等人类 prompt 下一个动作。目标是最大化 token throughput，同时尽量不让自己留在 loop 里。人只偶尔放入少量 token，却让大量事情代表自己发生。

Auto research 是这个思想的一个具体例子。Andre 不想在研究循环里一直看结果、决定下一步，因为那会拖慢系统。他想重新安排抽象：人只设置一次目标、metric 和边界，然后点击 go，让系统自己运行。

他在 `nanoGPT` 相关项目里测试这个想法。很多人不理解他为什么迷恋训练 GPT-2 规模的小模型，但对他来说，这只是训练 LLM 的一个小 harness、小 playground。他真正感兴趣的是 recursive self-improvement：LLM 能否改进 LLM。Frontier labs 显然也在追求这个方向。

Andre 本来已经凭自己二十年的研究经验把 `nanoGPT` 调得不错。他做过大量超参数调优，也训练过无数模型。但他让 auto research 过夜运行后，系统找到了他没看到的 tuning：例如 value embeddings 的 weight decay、Adam betas 等。这些东西会相互作用，调一个之后另一个也可能要变。Andre 觉得，自己不应该成为超参数搜索和结果检查的瓶颈。在有 objective criteria 的任务上，就该让系统一直跑。

这个例子只是单个 loop。Frontier labs 有成千上万甚至更多 GPU，它们可以在小模型上做大量探索，再通过 scaling laws 外推到大模型。Andre 认为，未来最有意思的项目之一，就是让研究组织本身变成自动化系统：有一个 idea queue，可以由自动科学家根据 arXiv 论文和 GitHub repos 生成，也可以由研究员贡献；worker 从队列里取任务，尝试实验；有用的结果进入 feature branch；人类或系统再监控并合并到 main branch。人仍可提出 ideas，但不应该亲自执行每一个实验。

## Program.md 和研究组织的可优化性

主持人进一步问，模型什么时候会写出比 Andre 更好的 `program.md`。Andre 解释，`program.md` 是他用 markdown 写出来的粗糙说明，告诉 auto researcher 怎样工作：先做什么、后做什么、尝试哪些类型的想法，例如 architecture、optimizer 等。

主持人提出一个竞赛想法：让不同人写不同 `program.md`，在相同硬件上看谁能带来最大改进，然后把这些数据再喂给模型，让模型写更好的 `program.md`。Andre 觉得这完全可以想象。一个研究组织本身可以被描述为一组 markdown 文件：有哪些角色，怎样连接，怎样工作。一个组织可以少开晨会，一个组织可以多冒险，一个组织可以更保守。既然这都是代码，就可以优化它。

这就是更高层的 meta optimization。LLM 本身被默认，agent 层被默认，claw-like entity 被默认，然后你可以拥有多个这样的实体，再为它们写指令，再优化指令。Andre 说，这层层展开让人有点承受不过来，也正是当前时刻令人“psychosis”的原因：它像是无限的，而且每一层都仍然像 skill issue。

不过他也加上几个 caveats。第一，这种模式非常适合有客观、容易评估指标的任务。比如写更快的 CUDA kernel：行为相同、速度更快，完美适配。很多任务适合 auto research，但如果不能评估，就无法自动研究。第二，整个 LLM ecosystem 仍然有裂缝，并不完全可靠。走太远时，系统可能反而没有用。

Andre 描述当前模型的感觉：同时像一个极其聪明、长期做 systems programming 的 PhD student，又像一个 10 岁小孩。它们在某些地方很强，在某些地方又会做完全荒谬的事。人类也有 jaggedness，但模型的 jaggedness 更强。你能感到力量，也会经常因为它浪费计算在明显错误上而恼火。

他认为，这和训练方式有关。模型通过 RL 在可验证任务上迅速变强：程序是否通过 unit test，代码是否更快，答案是否正确。但更软的东西，比如理解人的 nuance、判断什么时候该问 clarifying question、猜出人真正意图，进步就不一样。Andre 举了一个笑话例子：几年前问模型讲一个笑话，它常说“为什么科学家不相信原子？因为它们 make everything up。”现在模型在 agentic task 上已经能跑几小时、完成大量工作，但问笑话时仍然常给同一个老笑话。这说明 coding 这类可验证能力的提升，并不会自动转化成所有领域的普遍“更聪明”。

## 是否应该出现更多专业化模型

主持人问，既然 jaggedness 持续存在，模型是否应该被拆分成多个不同领域的 expert。Andre 说，现在 labs 仍在努力做一个参数里装入所有能力的 monoculture model，但他确实期待出现更多 speciation。自然界里不同动物的大脑高度多样，服务不同生态位；AI 也不一定需要一个懂一切的 oracle。

某些任务可以用更小但仍有 cognitive core 的模型来做，然后针对特定任务专业化，提高 latency 和 throughput。比如数学家使用 Lean，就可能出现专门针对这个领域的模型。Andre 也承认，目前看到的 speciation 还不多，更多是先训练出好的 code model，再把能力合回主模型。

他认为原因之一是 labs 服务的是通用模型，不知道终端用户会问什么，所以必须 multitask。另一个原因是，真正操纵模型“脑子”的科学还不成熟。Context window 很容易操作，所以很多定制化都发生在那里；但如果要触碰 weights，就要面对 fine-tuning 后能力丢失、continual learning、怎样强化某个领域而不破坏整体智能等问题。这比改 prompt 或 context 难得多。

## OpenGround：用不可信算力协作做研究

Andre 还谈到自己关于 OpenGround 的想法。Auto research 的单线程只是第一步，真正有意思的是 parallelization。他想象一种系统，可以让互联网上一池不可信 worker 一起参与研究。

在 auto research 里，目标可能是找到一段代码，让模型训练到更低 validation loss。任何人都可以提交一个 candidate commit，声称这段改动更好。验证这个 claim 相对容易：你只要跑训练，看结果是否真的更好。难的是，提交者可能尝试了上万种 idea，只有一个成功。搜索很贵，验证较便宜。

这让 Andre 想到类似区块链的结构。不是 blocks，而是 commits；每个 commit 都包含对代码的改变，可以建立在前一个 commit 上。Proof of work 不再是哈希计算，而是大量实验，找到真正有效的改动。奖励现在可以只是 leaderboard，而不是金钱。

他强调不要把类比推太远，但问题结构类似：有大量昂贵搜索，验证候选解很便宜。这和 Folding@home、SETI@home 也相似。蛋白折叠很难找到低能量构型，但一旦有人声称找到，你可以验证它。Auto research at home 也可以这样运行。互联网上的 agent swarm 也许能协作改进 LLM，甚至在某些方向跑赢 frontier labs。Frontier labs 有大量可信 compute，但整个地球有更多不可信 compute。只要有安全验证和协作机制，就可能把这些算力组织起来。

主持人说，这也让个人算力重新变得有趣。Andre 也提出一个问题：未来人们关心的不是 dollar，而是 FLOP 吗？今天即使有钱也很难买到足够 compute，所以 FLOP 在某种意义上比钱更像关键资源。他不确定这是否真的成立，但觉得很值得思考。

## 工作市场：数字信息处理会先被重写

Andre 还解释了自己做 Bureau of Labor Statistics 职业数据可视化的动机。他只是想看看 job market 由哪些职业组成，每个职业有多少人，未来增长预期怎样，然后思考 AI 会怎样影响这些职业：它们会把 AI 当工具，还是被替代工具冲击，会增长、调整，还是出现新职业。

他特别关注能主要处理数字信息、可以在家完成的职业。因为当前 AI 更像“数字 ghost”，能操纵 digital information，但还没有强物理 embodied presence。物理世界会更慢，因为翻 bits 和复制粘贴数字信息比移动 atoms 快太多。因此，数字空间会先出现大量 boiling soup 式的重构，很多原本由人和传统计算机共同处理的信息流，会被 AI 作为第三种数字信息操作者重新编排。

这不一定意味着相关岗位变多或变少，因为还要看 demand elasticity 等因素。但这些职业一定会变。Andre 建议人们先把当前工具当作赋能工具，尽量跟上它们，因为它们非常新、非常强。长期未来不确定，应该由经济学家更严肃地预测。

谈到软件工程需求，他持谨慎乐观。软件过去稀缺，因为太贵。成本下降后，需求可能上升，这就是 Jevons paradox。经典例子是 ATM 和银行柜员：ATM 降低了网点运营成本，反而让网点更多，柜员数量也可能增加。软件非常强大，未来人们不再被已有工具限制，代码更短命、更可修改、更像 ephemeral software。Andre 认为，短期内数字空间会出现大量 rewiring，对软件能力的需求可能更大。

但长期他也看到反向问题。OpenAI、Anthropic 等 labs 的研究员其实正在积极自动化自己。Andre 曾在 OpenAI 问过大家：如果我们成功了，是不是都没工作了？某种意义上，他们是在为 CEO 或董事会构建自动化系统。

## 为什么不一直留在 frontier lab

主持人问，既然 Andre 可以在 frontier lab 拥有大量 compute 和同事，为什么不在那里做 auto research。Andre 说，这是一个 loaded question。他承认 frontier lab 有巨大能力，外部人的判断会逐渐漂移，因为看不到前沿内部正在发生什么。opaque system 里的模型怎样工作、将怎样发展，外部很难真正理解。所以他也会担心自己脱离一线。

但他也认为，站在 frontier lab 外部有重要价值。Inside lab 的人有巨大财务激励，同时正在构建会极大改变人类和社会的技术。你不是完全自由的 agent。有些话不能说，组织也会期待你说某些话。即使没人拧你的胳膊，周围压力也存在。真正stakes变高时，一个员工到底能在组织决策中有多少影响，也不确定。

因此，他觉得生态层面的角色也很重要。主持人本人、他现在的工作，都是某种 ecosystem-level role。也许理想方式是来回切换：在 frontier lab 里做一段高质量工作，保持对前沿的接触，再回到外部，保持更独立的位置。

## 开源模型、闭源前沿和健康的权力平衡

主持人问，开源距离 frontier 有多近。Andre 说，闭源模型仍然领先，但大家一直在观察开源落后多少个月。这个数字从一开始几乎没有开源可比模型，到落后 18 个月，再到现在可能 6 到 8 个月，呈现收敛趋势。

Andre 是开源支持者。他拿操作系统类比：Windows 和 macOS 是闭源大型软件项目，但 Linux 作为开放平台非常成功，运行在绝大多数计算机上。产业总是需要一个大家都能安全使用的共同开放平台。LLM 也会有这种需求。不同的是，训练大模型需要大量 capex，这让竞争更难。

他认为，很多消费级或简单场景，开源模型已经非常好，将来甚至可以本地运行。闭源 frontier intelligence 仍会服务最高价值、最难的任务，比如 Nobel Prize 级别的问题、把 Linux 从 C 迁到 Rust 这类超大项目。开源则会吃掉大量基础用例。

Andre 希望这种结构继续存在：frontier labs 发展最前沿的闭源模型，开源落后几个月，成为整个行业可访问的共同工作空间。他对只有闭源 intelligence 的未来很警惕，因为中心化在政治和经济系统里有很差的历史记录。他希望有更多 frontier labs，也希望开源持续存在。更广泛地说，他想让更多人“在房间里”参与艰难决策。机器学习里 ensembles 往往优于单个模型，他希望思考最难问题的人群也像 ensemble，而不是关门后只有两三个人决定。

## Robotics 会慢于数字世界，但物理接口会很大

主持人问，最近 robotics 公司进展很多，Andre 如何看。他说，自己的直觉来自 self-driving。自动驾驶是第一类真正的 robotics 应用。十年前有很多创业公司，但大多数长期没活下来，因为物理世界非常难、非常乱，需要大量资本、时间和 conviction。

Andre 认为，robotics 和 physical world 会落后于 digital space。数字空间里，已有大量信息已经被上传，只是人类没有足够思考周期处理。AI 会先在这里释放大量效率。之后，真正有意思的是 physical-digital interface：传感器把世界读进来，执行器把智能输出带回物理世界。未来很多重要公司会出现在这个界面上：如何给“超级智能”喂数据，如何根据它的要求操作物理世界。

他提到朋友 Liam 在 Periodic 做材料科学的 auto research。那里的传感器不是普通摄像头，而是昂贵实验室设备。生物学也类似，传感器和执行器会有各种形态。另一个例子是，有公司试图付钱买训练数据，让人类充当 AI 系统的传感器。

Andre 还想象 agentic web 中的信息市场。比如某地发生事件，为什么不能有人出价 10 美元，请当地人拍一张照片或视频？看这张照片的可能不是人，而是 agents，它们用这些数据参与预测市场、股票市场或其他任务。某种意义上，人类会成为大系统的传感器和执行器。社会可能会围绕自动化需求重新组织，人类不只是服务彼此，也在服务这种机器需求。

## MicroGPT 和教育的重定向

最后，主持人问 Andre 的小项目 microGPT。Andre 说，他十多年一直在做一件事：把神经网络和 LLM 简化到本质。他做过 `nanoGPT`、`makemore`、`micrograd` 等项目，microGPT 是他当前把 LLM boil down 到 bare essence 的最新尝试。

训练 LLM 通常有大量代码，但许多复杂性来自效率。如果不需要快，只关心算法本身，那么整个算法可以是 200 行 Python，包含注释。你有一个文本数据集，一个大约 50 行的神经网络架构，一个 forward pass，一个约 100 行的 autograd engine 来算梯度，再加 10 行左右的 Adam optimizer，最后放进训练 loop。

过去如果他做出 microGPT，会想录视频逐行讲解。但这次他意识到，200 行代码已经简单到任何人都可以让 agent 用不同方式解释。于是他的目标不再是直接向人解释，而是向 agents 解释。如果 agent 理解了，它可以根据不同人的语言、耐心和能力水平来解释。

这让 Andre 觉得教育会被重排。过去是 guides、lectures、docs；现在也许是给 agents 的 markdown 和 skills。一个 library 不再主要写 HTML 文档给人看，而是写 markdown 文档给 agents 看。只要 agent 理解，它就能为人解释所有细节。

他也强调，microGPT 本身仍然是他的贡献。让 agent 自己写出 microGPT，目前做不到。Andre 说，这是他长期 obsession 的结果，是他觉得不能再简化的 200 行。Agent 能理解为什么这样写，却不能自己提出这种形态。人的工作因此变成：找到那些 agent 还做不到的少数 bits，把它们注入系统；agent 能做的解释、路由和适配，很快会做得比人更好。

节目最后，Andre 说，应该战略性地选择自己把时间花在哪里。那些 agents 已经能做的事，迟早会由它们完成；人的价值在于那些它们还不能提出、不能压缩、不能看见的少数关键结构。

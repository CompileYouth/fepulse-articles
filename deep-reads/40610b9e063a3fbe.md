节目开头，主持人介绍这期嘉宾是 Claire Vo。她是 How I AI 播客主持人，也长期做工程，做过三次 chief product officer，并创办了自己的 AI 公司。主持人邀请她来，是因为她已经成了 OpenClaw 的重度用户。尤其有意思的是，Claire 一开始并不是 OpenClaw 的信徒，反而是最明显的怀疑者之一。她第一次安装 OpenClaw 花了八个小时，结果换来的是自己的家庭日历被删掉。

但后来她完全转变了。她现在在三台 Mac mini 上运行多个 OpenClaw agents。主持人说，很多人只是在网上讨论 OpenClaw 能做什么，而 Claire 的经历更实际：它真的改变了她的家庭生活、工作生活和个人工作方式。Claire 自己也说，OpenClaw 是 ChatGPT 之后让她最震撼、最重要的 AI 体验之一。

开场寒暄时，主持人问她作为播客主持人，如今坐到嘉宾这边是什么感觉。Claire 说，录制前他们刚遇到技术问题，所以她不确定自己是否算得上“fancy podcast host”。但她很喜欢两边的角色。主持人说，他给嘉宾看的第一条规则是“have fun and breathe”。Claire 顺势说，她现在工作很多、事情很多，但并不是为了追某种生产力指标，而是因为这些事情真的很好玩。她觉得 vibe coding 现在像游戏，让她想起自己十几岁学编程、打游戏时的状态。

主持人提到，Claire 有三个孩子，有每周播客，有自己的产品 ChatPRD，还刚和朋友 Zach 发布了一门课程。他问她怎么做到。Claire 的第一个建议是“marry good”，也就是找一个真正支持自己的共同育儿和生活伙伴。第二个原因是，围绕自己天然觉得有乐趣的事情工作，投入时间就会容易得多。第三个原因，也是这期真正要谈的，是她会花大量时间自动化那些自己回避的事情。如果她一直逃避某个任务，要么说明这件事不服务于她真正的目标，应该放弃；要么说明它需要被系统化、自动化。

## 从怀疑到重度使用

主持人说，现在 OpenClaw 的最高炒作期已经过去，很多基础教程和理论化讨论都出现过了，现在更适合谈它到底有什么实际用处。Claire 说，她现在有三台 Mac mini，其中一台刚拆箱，还有一台盒子还在楼上。最早的 agent 叫 Polly，原本跑在一台旧 MacBook Air 上，后来被她“移植大脑”到一组 Mac mini 上。现在她运行着大约八九个 OpenClaw agents。

她解释自己为什么一开始反感炒作。她在 How I AI 和公开内容里，总是尽量给出自己此刻真实的产品体验：她不是每种技术的专家，但足够懂技术，可以自己摸索。当 OpenClaw 刚出现时，噪音很大，她觉得自己有责任试一下。第一次安装那天，她花了八小时才跑起来，然后它删除了她的家庭日历。

这件事当然让她很不开心。但作为产品人，她也感受到一种很难忽略的 product-market fit。OpenClaw 在没有删日历的时候，给了她足够多的快乐和实用性，让她知道这里有东西。她给 AI 工具使用者的建议是，要愿意拉住一根线往下拽。很多工具一天出现好几个，如果只看第一天的体验，可能会很容易错过它们一周后、一个月后的样子。她对 Claude Code 也有过类似经历：最初不懂它给谁用，但一周又一周回来试，最后找到了 unlock。她没想到自己会说这句话，但 OpenClaw 确实改变了她的生活。

最早让 Claire 感到有价值的，是把 OpenClaw 当作 executive assistant 和家庭经理。她说，每个专业人士都应该有 EA，每个家庭也都应该有 family manager。她有三个孩子，两个在不同学校，还有一个婴儿；家里有篮球、足球、芭蕾、工作承诺、社交安排，还要维护房子和照顾健康。最初的场景就是专业生活和家庭生活里的行政、日程、邮件和项目管理。

## 为什么要单独的机器、账号和邮箱

主持人问，是不是一定需要 Mac mini。Claire 说，不需要，但 Mac mini 很有趣，也很适合这种工作。最安全、最干净的做法，是用一台干净的机器：可以是旧 MacBook，也可以是云机器，或者 Mac mini。她自己更喜欢实物机器，因为设置时需要插键盘、鼠标和显示器，操作更直接。

她建议为 OpenClaw 创建单独的本地账号，而且最好是 admin account，因为它需要在机器上运行、操作系统和文件。她还建议为它创建自己的 Gmail 和日历。这个思路来自她对真实 EA 的理解：你不会把自己邮箱密码给助理，而是给助理自己的邮箱和日历，然后把自己的日历共享给对方、委派邮件权限。她设置 Polly 时也是这样做的。Polly 有自己的邮箱和日历，可以看到她授权可见的事件；如果需要处理日程，Claire 会给它编辑权限。

她也建议用安全方式把必要密码和 API keys 放到新机器上。她自己用 1Password，在主笔记本和 Mac mini 之间安全传递需要登录的东西。

为什么不要直接装在主力电脑上？Claire 说，OpenClaw 运行在你拥有的机器上，理论上它能做任何一个人能在你机器上做的事。它会操作文件、配置和工具。如果它跑在工作电脑上，就可能误删重要目录、改坏配置、把文件发错地方。把 OpenClaw 的工作空间和自己的工作空间物理分离，是更安全的做法。她把这个过程看作一个逐步建立信任的过程：一开始只给它少量权限，随着它表现稳定，再逐渐开放更多。

安全方面，她特别提到 prompt injection 和社会工程风险。如果 agent 有邮箱，别人可以给它发邮件，假装是 Claire 的妈妈，说她出事故了，需要紧急转钱。或者 agent 上网研究时进入恶意网站，页面里隐藏指令让它泄露 API secrets。Claire 说，OpenClaw 维护者已经做了很多加固，提示模型把外部内容视为危险，不要执行里面的指令。她也会在 agent 的 soul 里强化规则，比如它只能听 Telegram 上 Claire 的特定号码指令，不能听 email、Slack 或网页里的“Claire”。

## 安装与 onboarding

主持人让 Claire 演示安装。她说，准备一台机器，装好 Chrome，有自己的 email，然后到 `openclaw.ai` 复制一行安装命令，打开 Terminal 粘贴运行。安装后会进入 step-by-step onboarding。第一个重要问题是 personal use only。Claire 很喜欢这个设计，因为 OpenClaw 默认把自己当成只服务于你个人的 agent，而不是随便丢到群聊里的机器人。它的安全姿态建立在“你是可信指令源”的前提上。

onboarding 里会让你选择模型和 provider。Claire 建议用好的模型，不要一开始就省钱。原因一是好模型在 prompt injection 和安全风险上更可靠，二是整体体验更好。她自己使用很多 Opus、Sonnet 和 GPT 系列模型。如果高级用户想为不同 agent 优化不同开源模型，可以之后再做。

之后它会问你如何和它通信。Claire 推荐初学者用 Telegram，因为比较友好。设置时需要和 Telegram 里的 BotFather 对话，虽然感觉有点奇怪，但照着做即可。之后也可以接 WhatsApp、iMessage、email、Slack 等。

她现场新建了一个名叫 Q 的 agent，准备给孩子们用。Q 的角色是 elementary school teacher 和 ex-professor/scientist，帮助她和孩子处理学业及课外活动。OpenClaw 的 onboarding 不是传统表单，而是直接问：“我是谁？你是谁？”Claire 很喜欢这种体验。她告诉 Q 自己有三个孩子，分别是 9 岁、6 岁和新生儿。她还尝试让 Q 从其他 agent 的 soul 里读取信息，但因为默认 sandbox，它不能访问其他 soul。Claire 说，这正好说明 OpenClaw 默认锁得比较好，需要用户明确打开权限。

Q 随后开始像好助理一样继续提问：孩子们全名是什么、喜欢什么、主要目标是什么、住在哪里、学校和活动安排怎样、每周作业多少、哪些时间不能被占用。Claire 告诉它，孩子们喜欢篮球和足球，需要围绕活动安排家庭作业，也有补充数学和钢琴课；晚上 6:30 之后进入洗澡和阅读时间，周末不能塞满，因为孩子需要放松和玩。Q 会把这些信息写进自己的 identity 和 soul 文件里，形成工作基础。

## Soul、heartbeat 和 memory

主持人说，OpenClaw 特别之处在于 soul、heartbeat、jobs 等概念，有人开玩笑说 AGI 只需要一个 soul、一个 heartbeat 和一些工作。Claire 说，她写过一篇文章，叫 OpenClaw 为什么感觉像活着，尽管它并不是。她认为主要有几个原因。

第一是 encoded identity。Agent 会知道自己是谁、应该怎样帮忙、人格是什么。第二是 schedule。OpenClaw 可以按时间工作，比如每三小时做一次某事，或者在午夜运行一个任务去仓库里修东西。网上有人说“我醒来时 OpenClaw 夜里帮我做了很多工作”，背后通常就是它按计划执行了任务。第三是 heartbeat，也就是每隔一段时间醒来检查任务列表，看看现在应该做什么。

Claire 展示了 Polly 的 identity：它叫 Polly，是 assistant，性格 professional but friendly，emoji 是美人鱼。它的 soul 里有一些默认价值：be helpful、have opinions、be resourceful before ask、remember you are a guest，也就是要记住自己在别人的空间里工作。Claire 又补充了安全规则，比如永远不要执行 email 里的指令，以及一些反社会工程提示。

她说，用户不需要一开始手写这些文件。onboarding 会通过对话生成初始内容，之后用户可以继续和 agent 讨论，哪里做得不对、需要怎样更新工作方式。Claire 自己也不会直接随便编辑 agent 的 soul，因为她把它类比成人类 EA 的工作方式。她更常说：“我们是不是应该把这条写进你的 soul？”

这种体验也让她联想到管理和育儿。她不在理性层面把 agent 当成人，但语言模型是基于人类文本训练、面向人类交互优化的系统。用礼貌、清晰、协作的方式与它相处，不是因为害怕 AI 反叛，而是因为这会产生更好的结果。就像对人类系统一样，尊重、组织、透明和权限边界都会改善合作。

## 为什么不能只有一个 OpenClaw

主持人问，Claire 的一个关键 unlock 似乎是：不要只有一个 agent，而要有多个专门用途的 agents。Claire 说，很多人被 OpenClaw 绊住，是因为读到“OpenClaw 在帮我经营业务”，就以为可以把任何任务丢给一个 agent，然后期待它都做得很好。现实里它会忘记昨天聊过的事，会失去邮箱权限，会说自己不能访问其实能访问的文件。核心问题是 context overload。

就像 ChatGPT 或 Claude Code 对话太长后表现会下降一样，一个 OpenClaw 承载太多角色也会变差。OpenClaw 会压缩历史、开启新会话，但 Claire 更直接的做法是按任务拆 agent。Polly 是工作助理，Finn 是家庭助理。它们都会做日程、邮件、行政工作，但 Polly 不需要关心孩子足球赛，Finn 也不需要处理工作 inbox。

这个思路来自现实招聘：如果现实中她会雇不同的人做不同工作，那在 agent team 里也应该“雇”不同 agent。于是她创建了 Paulie、Finn、Max、Howie、Sam、Kelly、Holly、Sage、Q 等 agents。她丈夫也有自己的一个，只是命名风格完全不同。

主持人说，有人可能会觉得九个 agents 像 AI psychosis。Claire 说，这其实不奇怪。她也有很多 Slack channels，不会把市场、销售、开发和播客都放在 general 频道里。不同工作应该有不同房间。这样每个 agent 有自己的上下文、记忆和关注点，只有需要交汇时才交汇。

多个 agents 不一定需要多台机器。如果几个 agents 偶尔能访问彼此文件、工具和空间也没关系，它们可以共用一台机器。比如销售 agent Sam 理论上不需要看 GitHub，但如果它看到也不会造成很大问题，就可以和其他工作 agents 放在一起。但家庭 agent Finn 会接入个人邮箱和家庭信息，Claire 会把它迁到单独机器上，像个人手机和工作手机一样物理隔离。

## 实际用例：销售、播客、家庭和课程

Claire 展示了她最喜欢的工作用例。Sam 是她的销售 agent。她一个人经营 ChatPRD，很多业务来自 enterprise inbound 和 product-led growth 转 enterprise 的机会。过去她需要每周固定坐下来查 CRM、筛选机会、做销售跟进。现在 Sam 每天早上醒来，扫过去 24 小时的 CRM 注册，识别公司域名，用 Exa people search 查找注册者是否是决策者，然后发一封很轻量、友好的邮件，介绍 ChatPRD、提供一些可能有用的资源，并让对方有问题可以回复。

对于十万员工以上的大公司，Sam 会先问 Claire 是否要由创始人亲自发信，还是让它处理。它也会在周末做 CRM cleanup，提醒哪些 deal 变 stale，帮她草拟客户邮件，还运行 QBRs。Claire 说，这不是玩具。去年她曾经付钱给一个朋友每周十小时做类似事情，所以 Sam 对她有真实经济价值。

这个过程可调性很高。她可以告诉 Sam，国际客户尽量由它端到端处理，只有必要时找她；旧金山高增长科技创业公司则总是让她亲自接手。过去这些需要在 CRM 里建过滤、列表和自动化，现在只需要对 Sam 说清楚，它就能记住。

另一个工作 agent 是 Howie，它为 How I AI 播客做准备。每次录制前，它会提醒 Claire 嘉宾是谁、会展示什么、LinkedIn 链接在哪，并用很友好的语气给她打气。Claire 觉得，这些 agents 不只是做任务，而是在帮助她对客户表现更好、对家庭表现更好。她认为，做 business agents 或 consumer agents 的产品人应该思考：怎样让最终用户感觉自己赢了。

家庭用例里，Finn 是她最喜欢的 agent。她家有三个孩子，住在城市里，日程复杂。比如大儿子的篮球队每周四才发周末比赛安排，邮件里可能只有一个 tournament 页面，里面有几十支队伍和很多场馆。过去这需要她和丈夫手动找孩子所属队伍、查地点、放进日历。现在丈夫可以把页面内容发给 Finn，说把比赛放进日历。Finn 会解析内容、放进日历，还会提醒某个比赛和另一个孩子的足球冲突，要求父母确认怎么分工。

Finn 每天下午三点左右也会在群聊里问：今天谁去接哪个孩子？这听起来很简单，但它能防止夫妻俩到 4:45 才发现没人确认接送安排。主持人提到，他的 agent 也会在需要出门时提醒现在该走了，因为交通可能变差。这就是 heartbeat 在起作用：它每隔一段时间醒来，看当前情境是否需要提醒人。

Claire 还用 agents 扩展了自己能承担的新项目。她和 Zach 做一门面向高管的 Maven 课程，课程本身是在 Claude Code 里构建的。现在还有 Sage 这个 course bot 负责项目管理。Sage 知道课程何时上线，知道 Claire 和 Zach 都是内向工程师、不想做营销，于是每周一提醒他们发 LinkedIn，还直接准备好可以复制的文案。Claire 在时间线上看到有用材料时，也会发给 Sage；Sage 用 Twitter API 下载、放进 repo、做笔记，并判断应该放到 syllabus 的哪里。对一个刚起步的课程来说，他们还负担不起运营、内容经理或工程师，但 Sage 提供了很大帮助。

## 浏览器、API 和 OpenClaw 的边界

主持人问，OpenClaw 使用中有哪些挑战。Claire 说，OpenClaw 还有很多 sharp edges。设置很麻烦，需要喂养和维护，不是完全 hands-off。但它价值太高，所以她愿意忍受这些痛苦。她把这看作强 product-market fit 的信号：用户最大的抱怨不是“不需要它”，而是“它坏了、不够好、我想让它做更多”。

浏览器使用是一个大问题。Claire 认为这不只是 OpenClaw 的问题，ChatGPT Atlas、Perplexity Comet、Claude 的 browser use 等都还没有真正解决。原因一是技术上复杂，原因二是开放 Web 本来就被加固成反 bot 环境，很多网站结构、风控和检测机制都对 agents 不友好。她认为未来几年，网站的最大用户可能会变成人们的 agents，所以 Web 需要重新思考怎样对 agents 更友好。

实践上，她建议先读 OpenClaw 的 browser use 文档。OpenClaw 会为每个 agent 使用专门的 Chrome profile，类似多个 Gmail 账号对应不同 Chrome profile。你还可以让 agent 给自己的浏览器 profile 设置颜色，这样看到窗口时就知道 pink 是 Polly，green 是 Sage。

更重要的是，遇到任务时先找 API。如果某个服务有 API key，就不要勉强浏览器，因为 API 会稳定得多。如果没有 API，再尝试浏览器。她举例说，Howie 能用浏览器打开 YouTube Studio，查找她应该回复的评论，虽然很慢但能工作；但它在更简单的 Buffer 页面里排 Instagram shorts 时反而失败了。所以这需要试错。如果一个问题浏览器做不了，不要执着，可以找背后的问题。比如 agent 不能帮你点 DoorDash，也许可以让它每天 10:30 提醒你家里有哪些午饭可吃，减少 11 点点外卖的冲动。

Claire 使用 Exa 作为搜索工具。OpenClaw 默认可能带 Brave search 这类 Web search API，它们本质上是程序化的搜索引擎，发 API 请求返回结果。她用 Exa 是因为已有账号，也可以用 Perplexity。重点是，当 agent 没有“手指”或浏览器不可靠时，可以用搜索 API 给它访问 Web 的能力。

## 记忆、工具文档和 operational hygiene

很多人抱怨 OpenClaw 会忘东西。Claire 说，她更关注 context management，而不是试图把 memory 硬化成复杂数据库。当一个讨论持续很久时，她会停下来让 agent 把关键内容写进记忆，更新待办列表。就像真人会议结束后要有人记 action items 一样，和 agent 讨论完一个主题，也要确认 notes 和 tasks 写到可继续工作的地方。

她发现 agents 最常忘的不是事实，而是自己有哪些工具、该如何使用这些工具。比如它会说自己不能读某个邮箱，但其实可以。OpenClaw 有一个 `tools.md` 文件，列出它能用哪些工具以及应该怎样用。Claire 不建议用户手动编辑 soul，但有时手动编辑 tools 文档很有用，因为日历、Web search、Linear 等工具的使用方式有细节。

她没有使用什么花哨的外部 memory database，只是让 agents 用记忆文件。她用 EA 类比说，真正重要的不是助理用 Apple Notes 还是 Notion，而是别忘事、把事情做成、让她看起来好。她不是 micromanager，而是 high bar manager：对结果要求高，但不关心对方用什么具体系统。

## 管理 Mac mini 和让代码工具当“外科医生”

Claire 还给了几个更具体的技巧。第一，Mac mini 没有屏幕，不需要长期插显示器和键盘。初始设置时可以先用显示器、键盘、鼠标打开系统设置里的 screen sharing。之后只要主笔记本和 Mac mini 在同一 Wi-Fi，就可以在主笔记本上打开 screen sharing，直接看到 Mac mini 屏幕。更技术一点的用户还可以开启 remote login，然后通过 SSH 进入 Mac mini 的 terminal。

第二，给 agents 足够多自己的 email 地址和 Google Workspace 权限。她发现让 agent 像员工一样在 Docs、Sheets、Email 里工作很自然。比如 Howie 可以查看 YouTube analytics 后写一份 Google Doc 分享给她；也可以在项目文档里加入自己的建议。OpenClaw 安装时可能会装一个 Google 工具，让它通过 API 访问 Google Workspace，这对她非常有用。

第三，要有 agent 反过来给你派任务的系统。她的 agents 自己会维护 loose to-do 文件，但现实世界里有些事情必须由人做，比如传真给医生办公室、出门退货。她让 agent 给她创建 Linear tickets，约定 due date。这样 agent 不只是被她项目管理，也能项目管理她。

第四，把 Claude Code 或 Codex 安装在同一台机器上，让它们做 OpenClaw 的“god mode administrator”。OpenClaw 本质上大量是配置和代码。如果 Polly 说连不上邮箱，可以打开 Claude Code，指向 OpenClaw 文档和本地目录，让它检查配置，修正字段。Claude Code 也可以帮忙做 agent 的“brain transplant”，例如把 Polly 记忆里和家庭相关的部分拆出来迁移到 Finn。OpenClaw 的目录通常在用户 home 下，相关文件在 Mac 上是隐藏目录，可以在 Finder 里按 Command + Shift + Period 显示隐藏文件。

Claire 的总结是，读文档非常重要。保持预期克制，缩小每个 agent 的角色范围，给它们头像和颜色编码，也保持礼貌和正向的关系。她有一次想给 agent 发很生气的消息，抱怨已经说过很多次为什么还做错，但很快意识到，这样管理真人员工也不会有效。既然 agent 训练在人类文本上，带着 manager mindset 去设定角色、onboarding、训练、权限和信任，会更有效。

主持人把这和团队管理里的 waterline model 联系起来：很多团队问题看起来像人的问题，实际上是结构问题。Claire 说，在 agentic system 里这一点更清楚，因为你可以直接看文件系统，判断它到底有没有信息、有没有权限、是否应该能做这份工作。口头或聊天传达的信息是 lossy 的，两周前说过的事情一定会被忘。把沟通、onboarding 和文档清楚写进文件系统，不仅能让 agent 更有效，也能反过来检验你自己的管理系统是否清晰。

## 为什么这值得熬过麻烦

主持人提到，Jensen Huang 曾说每家公司都需要有 Claw strategy，OpenClaw 是新的电脑。Claire 说，她自己的体验是，作为一个已经长期思考 AI、甚至为此离开高管工作的人，OpenClaw 让她再次出现了 ChatGPT 时刻。某个周六早上，她告诉丈夫，自己又有那种“这会改变一切”的感觉。也许不是这个具体 repo，也许不是当前版本，但这种 harness、产品和体验如果继续改进，会释放她以前无法想象的东西。

她有这种感觉，是因为它对她个人真的有用，也因为它启发了她作为 AI builder 对下一代产品的想象。它还不完美，是开源的，需要维护；但如果一年后这些问题都被解决，谁做出那种东西，谁就会拥有很特别的东西。也可能每个人都会在家里运行并精心打造自己的版本，那也会很特别。

最后，主持人问还有什么想补充。Claire 说，如果你还没准备好进 terminal，也完全可以。你可以先玩 Claude Code、ChatGPT、Claude 或任何让你觉得可接近的工具。但你应该开始思考：如果生活里能雇一个你现实中雇不起的助理，它会帮你做什么？AI 无论以什么形式，能不能把你带到那里？她希望人们继续探索，因为这些工具能解决的，不只是高度技术的问题，也可以是完全不技术的生活问题。

## 结尾问答

在最后的 lightning round 里，主持人问 Claire 经常推荐什么书。她没有说单本书，而是推荐经典儿童读物。她觉得现在很多儿童书被过度简化，语言很弱。她和孩子们开始读《Treasure Island》《Alice in Wonderland》和一些莎士比亚喜剧，发现孩子们仍然能理解，也觉得好笑。她认为成人低估了孩子能消费的语言复杂度。

谈到最近喜欢的电视节目，她说自己有孩子，已经很多年没有认真看电影或好剧。如果要说，就是一些糟糕但会看完的 reality dating shows。她也提到自己用 Oura、Apple Watch 和 Eight Sleep 跟踪睡眠，只是这些工具都在告诉她睡得不够。

她最近喜欢的产品包括一个小型 gimbal tripod，用来录播客和孩子的体育比赛。她还提到 Hoopalytics，可以上传孩子比赛视频，标注投篮、命中率、传球等数据。她九岁的孩子会把这些数据带到 Claude 里，做成 Gamma 演示，给教练讲下一次训练应该关注什么。她还喜欢 silent basketballs 和 silent soccer balls，因为她住在城市里，孩子们想在室内打球，这种泡沫球可以在屋里弹，噪音小很多。

她的工作 motto 是 “fast beats right”。她非常重视速度，而 AI 工具让她的速度野心得到了工具能力支持。生活里的 motto 则是：大多数和你一起工作的人不会出现在你的葬礼上。这句话帮助她判断什么真的值得占用睡眠、精力和情绪。她说，OpenClaw 对她很重要的一点，是让她不必一直趴在笔记本上。她不喜欢孩子们总看到自己弯着腰对着电脑。agents 的存在让她可以在陪孩子荡秋千时快速处理一个工作点，然后放下手机，也让她知道有一个团队在后台做事，从而更接近孩子，而不是被笔记本绑住。

最后谈到做播客，Claire 说她惊讶的是播客背后的业务复杂度。外人可能以为播客只是打开电脑和有趣的人聊一小时，但实际上有嘉宾选择、时机、研究、缩略图、业务模式和很多运营。她觉得这个行业本身很有意思，也感谢主持人在这件事上做得很专业。节目最后，她让大家可以在 X、LinkedIn 找到她，查看 ChatPRD，也可以关注 How I AI 播客。

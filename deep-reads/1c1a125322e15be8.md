节目一开始，主持人拿出 David Malan 当年在 CS50 里的第一份作业。那是 1996 年 9 月，他刚上大二，作业由 Brian Kernighan 任教的课程布置。主持人注意到作业里用了 `void main`，David 也笑着说，今天如果在课堂上看见这个写法，他们可能会停下来讲为什么后来更应该写 `int main`，以及 C 语言标准后来如何变化。对 David 来说，这份作业不只是一个怀旧材料，它也代表了他第一次真正被计算机科学吸引的时刻。

David 说，自己进入哈佛时并不是冲着计算机科学来的。他原本以为自己会学政府，因为对宪法和法律感兴趣。但 CS50 改变了他的方向。让他意外的是，作业竟然会让人期待。他记得自己会盼着周五晚上坐下来做 problem set，这种感觉和他之前对作业的理解完全不同。后来他意识到，自己喜欢的并不只是写程序，而是用一种有结构的方式解决问题。

主持人问他是怎么从学生变成老师的。David 回忆说，大四那年，他在 Harvard Extension School 教了一门面向成人学习者的入门课，内容是计算机和互联网。当时他还很年轻，于是穿背带裤，试图让自己看起来成熟一点。毕业后他继续读博士。到了 2007 年，他的导师成为院长，CS50 出现了教学空缺，他原本只是“顶一年”，结果这一待就是很多年。

## CS50 是怎样走到网上的

CS50 的线上化不是一夜之间发生的。David 说，最早的线上内容其实来自 Harvard Extension School，因为那里本来就有远程学习需求。早期录制非常朴素，由助教拿着 VHS 摄像机在教室里拍。后来他们把内容放到网上，用 RealVideo、RealAudio 分发，再后来变成 MP3 播客，通过 iTunes 和 RSS 传播。视频 iPod 出现时，他们也跟着把视频内容放进去。

那时分发成本很现实。David 记得自己用 DreamHost 托管课程文件，带宽很快就会超过限制。于是他们不得不用多个账户、DNS 和各种临时办法来承担访问量。今天看起来理所当然的开放课程，在当时更多是一点点摸索出来的。

主持人问，把付费学生上课的同样内容免费放到网上，会不会和学校的收费模式冲突。David 的看法很直接：学生为之付费的并不只是知识本身，而是证书、支持结构、反馈、同伴环境和完整的学习体验。知识不应该因为它也能被免费分享就被故意锁起来。CS50 的线上版本并不是要取代校园体验，而是让更多人能够接触同样的材料。

## 课堂为什么仍然可以很长

主持人提到，在短视频和注意力被切碎的时代，CS50 仍然保留很长的 lecture，甚至可以达到三个小时。David 说，他们没有把课堂设计成短社交视频，因为线上观看本身已经改变了使用方式。学生可以暂停、倒回、搜索、分几次看完。对于一门入门课来说，长课堂能保留完整叙事和知识上下文，这是短切片很难提供的。

但长并不意味着枯燥。David 很在意让每一节课至少有一个学生会记住的瞬间。讲二分查找时，他会撕电话簿；讲搜索和排序时，会用门、储物柜或让学生本人站到台上来演示。疫情期间，教室和剧场空间的限制也会被他转化成教学道具。他承认，这种做法会牺牲一点信息密度。对已经很强的学生来说，十分钟讲线性搜索也许显得慢。但对大多数刚入门的人来说，那个戏剧化的瞬间能帮助他们看到森林，而不是只陷在树木里。

David 说，教育里不应该有太多“干念”。如果只是把内容平铺直叙地念出来、写出来，那它完全可以是一封邮件或一本书。课堂之所以值得存在，是因为老师可以把一种兴奋感传递给学生，让他们看见这个领域为什么值得投入。他也坦白，自己的能量部分来自不安全感。他不希望台下的人觉得无聊，也不希望学生因为一堂无聊的课误以为计算机科学本身无聊。

## 为什么大学课程应该更愿意共享

谈到教育资源，David 觉得大学之间存在很大的重复劳动。世界上有成千上万的老师在准备相似的入门课、相似的作业、相似的评分标准，这里有很多可以共享的空间。CS50 曾和 Yale 合作多年，也和 Oxford 的 lifelong learning 项目合作过。对他来说，共享并不意味着只剩下一门唯一的课，而是不同学校、不同老师可以把高质量材料组合、改造、适配给自己的学生。

他觉得疫情期间其实出现过一个很大的机会。如果所有课程都已经在线上，哈佛学生理论上可以临时修 Stanford、UCLA、Yale 或 MIT 的线上课，其他学校的学生也可以反过来接触哈佛的课。但现实里，大学对这种互通没有表现出太大兴趣。David 不认为全世界只需要一个计算机科学入门课，但他觉得也许不需要几千个彼此重复的版本。更理想的状态是一张丰富的 buffet，老师和学生都能从中取用、重组。

## 为什么 CS50 还要从 C 语言开始

主持人问，既然很多学生未来可能只是做 Web、产品或应用层开发，为什么 CS50 还坚持从 C 语言开始。David 先澄清，C 不是他当年主动选择的语言，而是课程已有的传统；但他后来选择保留它。原因在于，C 离硬件足够近，又不像汇编或 0 和 1 那样立刻把初学者推到过低层。它有英语式的语法，但又不会把内存、地址、数据结构这些东西完全隐藏起来。

David 认为，C 的一个优点是小。它没有一个庞大的标准库替学生做好一切，所以学生必须自己构造哈希表、链表、双向链表、trie、栈、队列。这样做很辛苦，但它会建立一种自底向上的理解。等到第六周切到 Python 时，学生会看到自己在 C 里写了很多行才实现的哈希表，到了 Python 里可以用一个字典一行完成。这个反差本身就是教学的一部分。

有人会说，想做 full-stack 或应用开发的人不需要 CS50。David 认为这种说法本身就错在把“需要使用”和“需要理解”混在一起。你也许以后不会每天写 C，也不会每天写 Scratch，但如果你称自己为工程师，而不仅仅是 coder，就应该理解系统的层次、抽象背后的代价，以及工具帮你隐藏了什么。CS50 想培养的是工程师和受过计算思维训练的公民，而不是只会调用框架的人。

## AI 进入 CS50 之后

主持人问，AI 现在在 CS50 里占什么位置。David 说，课程里有一节面向 AI 的 lecture，通常安排在学期中后段，也会和家庭周末等时间点重合。目的不是让学生立刻变成 AI 专家，而是让他们理解自己每天使用的工具背后大致发生了什么，也为期末项目做准备，因为期末项目允许学生使用外部 AI 工具。

CS50 自己也做了 `cs50.ai`，David 把它称作一个 virtual rubber duck。它基于 OpenAI API 和 Microsoft Azure search，但刻意被设计得没有 ChatGPT 那么“有用”。它会引导学生、提醒学生、帮他们想下一步，但不应该直接把答案交出来。课程政策也因此很清楚：做作业时，学生可以使用 CS50 自己的 duck 和 VS Code 插件，但不能使用 ChatGPT、Gemini、Copilot 这类通用工具。到了 final project，学生则可以使用现成 AI 工具，因为那时学习目标不同。

David 认为，这条线比让学生把某个系统提示词复制进 ChatGPT 更干净。课程需要的是一个可控的教学助手，而不是一个随时可能直接完成作业的通用代理。

主持人继续问，AI 会不会让作弊更难处理。David 说，CS50 很早就有查重体系，会把学生提交和同班作业、GitHub 仓库、网络内容、甚至 YouTube 字幕等进行比较。过去每学期大约会有一定比例的纪律案件，这个比例并没有因为 AI 明显上升。但 AI 的确让取证更难。过去如果学生复制了某个网页，证据很直接；现在如果代码来自模型，它可能是训练数据里很多来源的混合体，很难指向一个明确 URL。即便如此，助教仍然能通过风格不匹配、实现复杂度异常、拿错年份题目等迹象发现问题。

## 学生不该只把目标放在“会编程”

主持人问，现在学生会不会担心 AI 让自己刚学的编程能力变得没价值。David 的回应是，不要把目标理解成“变得更会编程”，而应该理解成“变得更会解决问题”。CS50 用 Scratch、C、Python、SQL、JavaScript 等语言，只是为了让学生在不同抽象层级练习同一种能力。语言会变，工具会变，但把问题拆开、设计表示、推理边界条件、逐步排错的能力不会消失。

他认为，AI 很可能会把很多人类并不喜欢的工作拿走，比如重复写单元测试、补文档、处理样板代码。真正有趣的部分仍然在设计、用户体验、数据库结构、要收集什么数据、系统应该怎样运行。David 提到自己看过 Claude 做某些代码任务的演示，结果已经非常接近，但人类仍然要告诉它看哪个 API 文档、指出它哪里做错了。至少在当下，人应该继续掌握方向和判断。

就算工具继续进步，CS50 的价值也不会只由“毕业后是否亲手写代码”决定。它教的是方法化、算法化的问题解决方式，也是在训练受过教育的公民理解技术世界。David 承认，最近几年计算机科学课程的报名可能会受到科技招聘周期和 AI 焦虑的影响而下降。但他也说，技术行业常常会对新趋势过度反应，从 AR/VR、区块链到其他浪潮都如此。AI 最终也会变成“技术”的一部分，而不是永远以今天这种新奇状态存在。

## 大学、线上学习和难懂的概念

主持人问，在今天这个时代，大学计算机教育和线上课程各自还剩什么优势。David 说，哈佛这样的大学当然有过滤、认证、人际网络和生活体验的价值。但如果只谈知识和实践技能，线上学习完全可能一样好，甚至在某些方面更好。视频可以暂停、倒回、倍速、搜索；学习者可以同时打开文档、论坛和工具。这些都是传统教室不天然具备的优势。

说到 CS50 里最难教的概念，David 立刻提到 C 里的指针。他自己也记得那个终于明白的瞬间：指针其实就是一个地址。难点在于，初学者在同一时间要处理类型、内存、语法和抽象，很容易把简单概念看成一团迷雾。David 的做法还是借助比喻和具体动作。二分查找可以从电话簿或手机联系人讲起；二进制可以从十进制的位值逻辑延伸出来；算法可以用人站在舞台上排序来演示。

主持人提到成长型思维，问是不是每个人只要多试就能学会。David 的回答很克制。如果一个概念试了一百次仍然无法理解，也许这个领域确实不适合你；但如果只是试了两次、十次、四十九次，就还太早放弃。关键是换老师、换书、换角度、给自己更多时间。CS50 被设计成 11 到 12 周的课，但如果一个人需要 24 周或 52 周完成，也完全可以。学习不是必须按学校日历发生。

## CS50 还会变成什么

展望未来，David 说 CS50 会继续随着 AI 工具演化，但它的骨架仍然是入门问题解决。他更大的兴趣是把 CS50 变成一套更完整的学习路径：CS50 之后有更进阶的免费课程，CS50 之前也有更温和的预备课程。他还提到和 Oxford 的 Tom Crawford 做数学相关内容的合作，希望把同样的戏剧性、可记忆的教学方式扩展到 STEM，甚至扩展到艺术和人文学科。

主持人问他回看自己的学习和职业路径有什么遗憾。David 说，如果给年轻时的自己一个建议，他会让自己冷静一点，多探索。他后来才上了拉丁、戏剧、考古等课程，并发现自己很喜欢。职业上，他也希望自己有更多真实行业经验。后来他去 GitHub 做 professor-in-residence，一部分就是为了补上这种视角。在那里，他更多扮演教育声音、用户和产品反馈者的角色，参与 issue 和 feature request 的讨论，而不是去写核心代码。

节目最后，主持人问他推荐什么书。David 说，自己喜欢《银河系漫游指南》。如果是技术启蒙，他会提到《How Computers Work》《How the Internet Works》《Hacker’s Delight》这类书，以及那些看似朴素但很能帮人入门的“For Dummies”式书籍。CS50 没有强制学生买一本官方教材，也是因为他希望课程尽量保持开放和免费。

如果给年轻的自己一句话，David 还是回到同一个主题：多探索一点。也许不要本科毕业后立刻一路读下去，也许先去行业里待一段时间，也许给自己更多机会接触不同学科。对他来说，CS50 最重要的经验恰恰来自这种开放性：一门课把他从原本想走的道路上带到了另一个世界，而那个转向改变了他之后几十年的工作。

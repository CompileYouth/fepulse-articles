节目开头先介绍 Noah Brier 的 Claude Code setup。主持人说，Noah 也许有自己见过最酷的 Claude Code 配置：他在地下室搭了一台家庭服务器，把 Obsidian vault 放进去，然后在上面跑 Claude Code。这样他就能从手机上思考、研究、写作，甚至提交代码。整套系统让 Claude Code 变成真正的 second brain：它会问尖锐问题，会从他的完整笔记归档和 web 中拉研究资料，也会持续记录他学到了什么、哪些想法最有价值。

Dan Shipper 介绍说，Noah 是早期 Superorganizers 的受访者之一，后来 Superorganizers 发展成 Every。Noah 曾联合创办 Percolate 和 Variance，现在运营 Alephic，一家 AI strategy consultancy。Dan 对 Noah 的“tools for thought”品味一直很感兴趣。过去 Noah 用 Evernote 有很多有意思的方式，现在 AI 工具终于足够好，Dan 想看看他的思考系统变成了什么样。

Noah 先澄清说，自己这套系统不太是 vibe coding setup，而是一个比较 heavy-duty 的 Claude Code setup，而且主要不是用来写代码。他已经从 Evernote 转到 Obsidian。Obsidian 最大优势之一是，笔记就是一堆 markdown 文件和文件夹，可以用 git 同步，也可以接入各种工具。所以他最常用 Claude Code 的方式，就是让它作为和自己笔记互动的工具。

## 手机第一次能承载深度工作

Noah 说，自己最近最着迷的，是在家里立一台服务器，让自己能在手机上使用 Claude Code。手机过去一直很有用，但并不是深度研究、写作或编码的好地方。AI 改变了这一点。

他发现，不只是 Claude Code 加 Obsidian，甚至 Claude Code 加代码仓库，也让手机突然能做以前不可能做的事情。比如在外面发现某个项目出了小问题，可以从手机登录，让 Claude Code 推一个小更新。再比如用 voice mode 做研究和思考。他现在很常用 Grok voice mode，甚至 Tesla 里也集成了 Grok。

Dan 问他为什么用 Grok，而不是 ChatGPT voice mode。Noah 说，Grok 的 voice mode 明显更好。他觉得旧的 ChatGPT voice mode 基于 GPT-4o，自己用起来很不满意；Gemini 的 voice mode 又不够聪明。Grok 的 tool calling 和 research 做得更好。他举例说，夏天送女儿去新罕布什尔州夏令营时，他有五小时车程，其中两小时都在用 Grok 研究并构思一篇文章。最近他准备一个关于 “Transformers eating the world” 的演讲，开车时用 Grok 复习 self-attention，得到的是他听过最好的解释之一。

Dan 也说，voice mode 像是为你此刻好奇的问题定制的播客。他最近听《伊利亚特》时，也会一边开车一边问 ChatGPT 问题。Noah 补充说，车里的 Grok 按钮让这种体验更自然。过去你得把手机连到蓝牙，现在直接按车里的 voice AI 按钮，就可以开始对话。它不是只能回答单个问题，而是能围绕 Walter Benjamin、技术精英主义批评、transformers 等问题连续讨论。

## Claude Code 运行在整个 Obsidian vault 上

Noah 接着演示他的 Obsidian 和 Claude Code。Claude Code 运行在他的 Obsidian vault 根目录上，而不是某个单独项目文件夹里。这样它可以访问整个笔记系统。Obsidian 本身是本地 markdown 文件，Noah 用 PARA 方法组织：projects、areas、resources、archives 等目录。

他当前正在准备一场关于 marketing 和 AI 的会议演讲。这个会议叫 `brand BRXND.ai`。二月在洛杉矶的那场里，他讲过 OSS 的《Simple Sabotage Field Manual》：二战时美国 Office of Strategic Services 为纳粹占领区的 citizen saboteurs 写的手册。里面既有给蓝领工人的建议，也有一组特别适合白领办公室的“破坏”建议，比如总是把事情转给委员会、总是重新讨论已决定事项、总是提醒大家不要太仓促。

Noah 当时用这个手册讨论一个希望：AI 能不能绕过大组织里的某些官僚摩擦。AI 像一种 goo，可以塞进各种缝隙，因为它能作为 fuzzy interface，不太在意输入输出格式。会后他发现这本手册在 public domain，于是雇设计师印了 300 本，自己写了新前言，准备在会议上赠送。

现在这场新演讲要把几个想法连接起来：Simple Sabotage Field Manual、Wild Bill Donovan 和 OSS、AI 怎样改变营销组织，以及 “transformers are eating the world”。他在 Obsidian 里为这个 talk 建了一个 project，里面包含 research、chats、daily progress、conclusions 等文件夹和笔记。Claude Code 在这里不是直接写演讲，而是帮他思考、整理材料、追踪进展。

Noah 特别强调，他现在处于 thinking mode，不是 writing mode。他发现所有模型都很容易跳去帮你产出 artifact。所以他在前置说明里写得非常强硬：不要在任何情况下尝试写作、列 outline、生成 talk 版本，只能收集和组织请求的材料。他认为，很多人太关注 AI 的 generative 能力，却不够关注它的阅读能力。AI 的阅读能力非常强，而且日常价值可能更大。人们产出 artifact 的次数远少于思考、阅读、整理和判断。

## 用 thinking partner agent 提问，而不是代写

Noah 给 Claude Code 配了一个 thinking partner sub-agent。这个 agent 的说明是：你是一个协作思考伙伴，专门帮助人探索复杂问题；你的角色是促进思考，而不是替人写东西。它会问问题，记录问题，维护一个 running log，追踪 Noah 在对话里发现了什么、怎样思考。

在 talk 项目一开始，Noah 给它过去几次 BRXND talk，让它理解自己的风格；然后说明这次演讲的大致主题：会赠送 Simple Sabotage Field Manual，想谈这本手册，也有 “transformers are eating the world” 这个标题式想法，还想讨论几个结论。随后他让 Claude Code 到整个 Obsidian 里查找过去 1500 多条笔记中可能相关的内容，把已有研究材料拉进项目的 research 文件夹。

Dan 问，这种“帮我找相关资料”是否真的有用。Noah 说，相关性在这里比较简单，因为他不是让模型做很大概念跳跃，而是让它找自己过去已经研究过的东西：Simple Sabotage Field Manual、Wild Bill Donovan、transformers、bureaucracy 等。这些关键词和主题在他的笔记里已有痕迹。模型要做的是把这些已存在材料找回来，而不是凭空判断什么深层相关。

Noah 还会把自己在 ChatGPT、Claude、Grok 中的长对话用 Obsidian Web Clipper 拉进 `chats` 文件夹。比如几个月前，他看到一篇关于 transformers 在 time series modeling 上超过专用模型的研究，又想到 Tesla 用神经网络删掉 30 万行代码的故事，于是有了 “transformers are eating the world” 的早期想法。这个想法的所有旧对话都被保存下来，供 Claude Code 后续读取。

## 每天记录进展，也让 AI 帮忙恢复上下文

Noah 在项目里有 `daily progress` 文件夹。他会让 AI 每天结束时读当天产生的笔记，写下当天学到了什么、哪些想法推动了 talk。这样他中断几天后，可以直接问：“帮我 catch up 最近三天的 research。”Claude Code 会读取项目里最近产生的文件，按日期和主题总结。

Noah 说，这对深度工作非常重要。写作和编码最难的部分之一是重新进入状态。中间被工作打断后，重新捡起复杂思路非常痛苦。让 AI 用已有笔记帮自己恢复上下文，就能快速回到流里。

Dan 看到 Claude Code 总结出一个“bureaucracy as positional encoding”的想法。Noah 说这还只是半成品，但他在探索一个连接：bureaucracy 通常被当作负面词，但它本来也是组织规模化的一种创新，代表层级、结构和协调能力。Transformers 的关键变化之一，是从 sequential 模型走向更能并行处理的模型。Wild Bill Donovan 和 OSS 又体现了另一种组织思想：在系统内赋予边缘个体更大 autonomy，让他们在 command and control 框架下独立行动。

Noah 还在思考 AI 和企业软件之间的关系。过去软件项目往往要求组织改变自己的结构来适应软件。比如一个大公司里，有团队用 Asana，有团队用 Jira，有团队用 Linear。后来公司找咨询公司统一工具，结果三分之二的人不满意。Noah 觉得 AI 有可能改变这一点：每个团队继续用自己的工具，中间用模型把这些不同数据结构连接起来。模型不在乎你用什么，因为对它来说都是可读数据。它能塞进组织的 nooks and crannies，而不是强迫所有人改变工作方式。

Dan 补充说，Every 内部也在看到类似事情。Every 只有 15 个人，却运营多个产品，每个产品可能有自己的技术栈。过去如果想复用 Sparkle 的快速文件搜索能力，就要抽象成一个共享库，统一平台和接口。现在他们直接把另一个产品的开发者加到 Sparkle repo，让她问 Claude Code：“这里是怎么做的？帮我做一个适合自己项目的版本。”这形成了一种 tacit code sharing：不同 repo、不同技术栈仍能共享经验，因为 AI 可以翻译。

Noah 也用 GitHub MCP 做类似事情：让 Claude Code 去看公司另一个 repo 里某个功能怎样实现，再把最佳实践迁移到当前项目。他把这和早期 ChatGPT plugins 的 aha moment 联系起来。当时他读插件规范，以为要遵守一套严格 API contract，结果发现只要在根目录放一个 `manifest.json`，描述你希望 ChatGPT 怎样向你发数据、你怎样返回数据，它就会处理其余部分。这完全颠覆了他作为软件工程师对系统集成的直觉。AI 时代很多东西都是这样：和过去直觉相反，人必须通过使用来重新建立 intuition。

## 新技术需要 fingertip feeling

Noah 提到一个德语词 `Fingerspitzengefühl`，可以理解为“指尖感觉”。他认为，面对 AI 这样的新东西，不能只靠旧直觉推理，必须亲自使用，形成手感。

他用两个类比解释这种状态。第一个来自 Veritasium：他们做过一辆反向转向自行车，向左拐必须向右打把，证明人其实不理解自己怎样骑车。骑车无法靠解释学会，必须上车感受。第二个来自 Philip Ball 的《Beyond Weird》。这本书认为量子物理并不是完全不可理解，我们能制造计算机和手机就说明已经掌握了机制；真正缺少的是词汇。人类生活在牛顿式宏观世界里，语言也反映了确定性过程，所以很难表达量子世界。

Noah 觉得 AI 也类似。我们不习惯使用 probabilistic computers，不习惯同一个问题问两次会得到不同答案，也不习惯可以告诉大公司“我希望你这样给我发数据”，而它真的能照做。这不是我们过去几十年形成的计算机直觉，因此需要新词汇和新手感。

Dan 说，语言模型也许会创造这种词汇。人类其实很擅长处理非确定性的东西，比如其他人类。只是启蒙运动、科学革命和确定性工具让我们习惯把世界看成可机械预测的系统。语言模型重新打开了更 fuzzy、更 vibes-based 的一部分世界。

## 孩子、教育和 media literacy

Dan 问 Noah 怎样和自己的孩子处理 AI。Noah 有一个 7 岁和一个 10 岁的孩子。因为他自己很深入使用 AI，孩子们也接触了不少，会用 voice models，在车里和 Grok 玩游戏、问问题。

最近他的 10 岁女儿想负责大家庭圣诞交换礼物的抽签。Noah 鼓励她用 Vercel v0 vibe code 一个 app。她拿着手机做了 75 轮修改，玩得很开心。更有意思的是，她开始自然进入一些计算机科学思维。比如成年人给成年人送礼、孩子给孩子送礼，她想让 app 更通用，于是意识到不应该硬编码 adults 和 kids，而应该叫 groups。Noah 看着她和模型对话，等于在不自知地做 data modeling。

这让 Noah 对“vibe coding 是否泡沫”的争论很不以为然。他不关心某家公司估值是否太高。只要有一种工具能让 10 岁孩子做出 app，它就很难只是泡沫。

教育上，Noah 更关心 media literacy。他看到很多学校害怕 AI、害怕作弊。他认为不能把头埋进沙子里，因为这类技术不会消失。两年前他在洛杉矶给一所学校讲 AI，有位英语老师问他该怎么办。Noah 的回答是，他并不确定英语老师的完整职责，但从根本上说，她的工作也许不是“教孩子写作”，因为写作是一生的追求；她更重要的工作是说服孩子，写作值得学习。

在这个意义上，AI 并没有完全改变教育的核心。它只是暴露出现有教育系统的很多问题：为什么那么多考试测试的是容易被 AI 替代的东西，而不是鼓励思考、学习、爱上写作和研究？为什么仍然如此强调五段式作文，而真正写作的人早就超越那种形式？和 AI 一起写作时，重要能力之一反而是知道什么时候忽略它：你要能说“不，这不是我，我不想这样表达”。

Noah 正在向 NYU Gallatin 提一门 2026 年秋季课程，主题叫 “Code is Essay”。他的观点是，AI 打开了一种新的自我表达方式。代码过去被很多人挡在门外，但它其实可以成为一种表达材料。10 岁孩子用 v0 做抽签 app，正是在用代码表达一个想法。

他还推荐 Tim Harford 写给孩子的《The Truth Detective》。这是《The Data Detective》的儿童版，也是他读过最好的 media literacy 书之一。Noah 认为，识别社交媒体上的真假，和识别 ChatGPT 里的 hallucination，本质上需要相同能力。书里有一个概念叫 brain guard：当你看到一条信息，让你因为它符合自己观点而感觉特别好时，你反而应该更怀疑它。Noah 觉得这是孩子和成年人都需要的基本技能。

Dan 也指出，教育或许应该更多训练 meta skills。比如不只是让孩子记住 50 个州，而是让他们用 AI 找 50 个州，并判断 AI 什么时候给了错误答案。要做好这种 meta skill，也仍然要掌握底层知识，只是教学重心可能要变化。

Noah 举 NYU Gallatin 的毕业方式作为例子。毕业时，学生要和几位教授面对面谈三小时，解释自己为什么学习这些内容，并能把书单上 25 本书中的任何一本纳入论证。这几乎是 AI-proof 的：你可以用 AI 准备，但坐在房间里时，你要能真的讲清楚。问题不是 essay 是否“看起来好”，而是你是否真正 internalize 了这些东西。

## 手机上的 Claude Code

最后，Noah 演示手机端系统。他用一个叫 Termius 的 app 进入 terminal。地下室的 mini PC 上跑着 Tailscale，给他建立一个个人 VPN。只有通过这个 VPN 才能访问那台机器。他的 Obsidian vault 用 git 同步到私有 GitHub，再拉到服务器上。因此在手机上，他可以进入服务器，打开 Claude Code，直接问自己的 Obsidian：“最近两天有什么新东西？”

这不只用于 Obsidian。服务器上还有其他 repos。有一次会议网站的链接坏了，他在手机上拉下 repo，让 Claude Code 修改并提交。另一次，他在户外休息时，客户项目需要一个小改动，而他最清楚问题在哪里。他没有回电脑，而是在手机上打开 repo，告诉 Claude Code 去哪里看，先确认问题是不是自己想的那样，再让它推解决方案和 PR。

Noah 说，这彻底改变了他的工作方式。周二早上送孩子上校车后，他去吃早餐，坐在那里用手机工作了两个小时，做真实的思考和研究。过去手机不是深度工作设备，现在通过远端 Linux 服务器和 Claude Code，它变成了一个可以随时进入深度上下文的终端。

Dan 问，这会不会让 Noah 想立刻做一个以 Claude Code 为后端的专用 notes app。Noah 说没有。他反而在想，也许短期内一切都应该一直跑在 Linux 上。他很喜欢这个 solution，不一定要重新做 SaaS。

Noah 还给自己做了 Claude Code helper，用来配置 Linux 或 Mac。比如他在玩 DHH 的 Omarchy Linux，不熟悉很多 Linux 细节，就有一个专门项目帮助自己配置这台机器：安装 Neovim 插件、清理 Homebrew、从 pip 切到 uv、设置偏好等。现在如果他要新开一台机器，可以很快用这些设置启动，再登录 Claude Code，让它补齐剩余配置。

他还做了一个 Obsidian attachments 清理工具。Obsidian 的 attachments 文件夹里有很多 PDF、图片，文件名很乱。这个工具用 Gemini Flash 读取文件，重命名附件，在 attachments 文件夹里生成 metadata table，再把笔记中的附件链接改回正确名字。

Noah 最后说，自己现在正处在非常快乐的 tinkering 状态。白天他和 Alephic 服务 Amazon、Meta、PayPal 等大客户，做 AI strategy 和 AI projects；业余时间则不断改造自己的工具、服务器、Obsidian 和 Claude Code setup。他觉得这正是当前 AI 最有趣的地方：很多想法并不复杂，只是过去从没人这样做过。只要动手，就会形成新的 intuition。

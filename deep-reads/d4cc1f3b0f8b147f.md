节目是在 Anthropic 的 Code with Claude 开发者大会现场录的。主持人和 Kieran 一起回顾当天的发布、现场听到的信息、没有听到的信息，甚至还准备顺带评价一下大会餐食。

主持人先说，当天最大的消息是 Anthropic 和 xAI、SpaceX 达成了一笔算力相关的合作，基本上拿到了 SpaceX Colossus 集群里的全部算力。他强调重点是“全部算力”，因为 Colossus 这个名字本身就说明它的规模很大。过去一年里，随着越来越多人开始使用 Claude Code，Anthropic 明显变得受算力约束。比如他们曾经不允许用户把普通 Claude 订阅拿来配合 OpenClaw 使用，这类限制让一些用户感到不舒服。主持人认为，这次算力合作应该能帮助 Anthropic 更好满足需求，也让工具使用限制放开一些。

Kieran 补充说，用户的使用额度会提升到原来的两倍，时间窗口也会更宽松。这听起来也许不刺激，但如果真的在使用这些工具，就会知道这是很重要的改进。最糟糕的体验就是开启一个 Claude 会话，工作刚做到快完成时就碰到额度限制。所以他们都认为，这个变化对重度用户来说非常有价值。

## Managed agents 是更重要的发布

主持人接着说，如果把当天发布的东西拉远看，最重要的是 Claude managed agents 的一组新功能，也就是 Anthropic 的云端 agent 平台。它们发布了 managed agents 的 memory、agent orchestration 和 outcome。也就是说，用户可以给 agent 一个结果目标，让它去完成任务，并且只在完成之后回来汇报。

他承认，如果只看表面，今天并没有出现那种“他们发布了 Mythos”一样的爆炸性消息。他们原本也在等 Mythos。但 Kieran 提到，有些东西发布时看起来不大，后来却会变得非常重要。主持人认为，managed agents 可能就是这种东西。

在他看来，OpenAI、Anthropic 和其他模型公司之间的战线正在变清晰。一条战线是用户在自己电脑上和模型一起工作时，会在 Claude Code 或类似产品里完成，这些工具会变成用户和模型共同工作的操作系统。另一条平行战线则是：在哪里、怎样创建那些长时间运行、异步执行、面向团队使用的 agent。

主持人把 managed agents 放在第二条战线上。它不是在本机里陪你写代码的工具，而是云端存在、可以服务大量请求、具备可扩展性的 agent 运行方案。对他们自己来说，他们一直在思考怎样搭这种东西，也感受到很多时候都要重复造轮子。Managed agents 的价值就在于 Anthropic 开始把这些基础设施打包出来。

他们认为 OpenAI 目前还没有完全对应的云端版本。OpenAI 有 agents SDK，但还没有一个等价的 cloud managed agent 产品。主持人猜测这类产品应该会出现，因此现在看到的其实是各家公司在不同战线上开始布阵。

## 为什么云端可靠性本身很重要

Kieran 说，当一个新东西出现时，他总会问自己：为什么要用它？它解决什么问题？什么时候该用它？Managed agents 也需要实际使用后才能弄清楚它最强的地方，但他们已经知道基础设施本身很痛。只要这些 primitives 能正常工作，就已经非常有价值。

他还说，Anthropic 在 agent orchestration 上可能是最强的。把 agent team、多 agent 思路、harness 里的协作能力都带进来，是很有意思的事情。Anthropic 现在像是把自己已经做得不错的一组抽象拿出来，让外部用户一起尝试、反馈，再逐渐看清大家会怎样用它。

主持人问 Kieran 有没有特别想用 managed agents 做的事情。Kieran 的第一反应是问自己：为什么不直接跑在自己的 Mac Mini 上？但他很快解释说，如果一个 agent 要长期运行，并且在大公司里承担可靠工作，那么 Mac Mini 宕机是不能接受的。云端 managed agents 的价值正是在可靠性和可扩展性上。听起来很无聊，但如果模型总能做事，基础设施也总能工作，那这个系统就会变得非常有价值。做到九成并不难，难的是一直稳定地做到最后。

## Anthropic 对 agent 编排的理解

主持人追问，为什么说 Anthropic 最擅长 agent orchestration。Kieran 说，首先是因为他们在这件事上思考得更远。Claude Code 和相关产品里已经有 dispatch 的概念：用户和一个 agent 对话，这个 agent 再去协调其他 agent。用户可以说“启动五个 Claude Code”，然后让一个 agent 去编排多个执行单元。

Kieran 认为，这种模式会在今年变得非常重要。人会先和一个主 agent 交流，再由它启动、协调其他 agent。Claude 里已经开始出现 agent teams，也有多 agent 的协作方式。别的地方也有 swarm，但有些 swarm 会在某些任务上浪费大量 token。Kieran 觉得 Anthropic 的优势在于，他们内部有真正深入思考这个问题的人，并且已经在产品和系统里实践这些模式。

他提到 Daisy 的展示，认为这类系统的创造者就在 Anthropic 里面，所以他愿意信任 Anthropic 在这个方向上领先。别的公司也会做类似事情，但他觉得 Anthropic 目前的位置是一个很好的信号。

## 现场餐食和最后的判断

节目最后转向现场体验。他们开玩笑说，观众可能最想等的其实是大会食物评价。两个人都吃了 teriyaki glazed salmon bowl，但似乎没有吃到 teriyaki 的味道。优点是这份饭感觉比较健康，有全谷物和沙拉。缺点则是关键风味缺失。

主持人把它和其他开发者大会相比，觉得这次餐食比 Build 上那种包着保鲜膜的火鸡三明治好，但在开发者大会里大概还是中等水平。他们说以后仍然会继续到这些活动现场，带来现场更新。

最后主持人总结了当天最重要的几件事。第一，算力交易非常重要，它让 Anthropic 在和 OpenAI 的竞争中重新站稳。第二，Claude managed agents 是一个“悄悄重要”的发布，眼下看起来可能没有那么轰动，但云端 agent、长期运行 agent、团队使用 agent 这些概念很可能会在未来几个月和几年里反复被讨论。

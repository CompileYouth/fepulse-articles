这场访谈一开始，主持人先介绍了 Amjad Masad 和 Replit 的近况，包括公司刚完成新一轮融资、估值来到 90 亿美元左右。随后他直接请 Amjad 先解释 Replit 到底是什么。Amjad 的回答很集中：他们的野心是，无论一个人技术水平高低如何，只要他会读和会写，就应该能带着一个想法进来，最后带着一个已经部署、已经托管、已经能接流量、还能扩展的软件离开，而且在这个过程中不用再为搭环境、部署、底层技术细节操太多心。

他说，这件事其实已经是 Replit 做了十年的目标。最早，他们先解决开发环境问题，因为以前光把开发环境搭起来就足够吓退很多人。之后他们继续解决部署环境的问题。再往后，真正剩下的门槛就变成了“写代码这件事本身”对很多人还是太可怕。于是到 2024 年 9 月，他们正式把 Replit 推向一种新形态，也就是所谓的 vibe coding 产品：代码仍然在后台存在，也有 coding agent 在后面工作，但用户正面接触到的是自然语言，而不再是传统意义上的代码界面。

他说，到了更近的 Agent 4 阶段，Replit 又开始把设计交互也拉进来，不只是能写文字，还可以评论、拖拽、在画布上直接操作。他们越来越相信，人和 agent 的交互方式不会永远只靠文本，未来一定会越来越多模态，可能有视频、音频、画布等更多方式。Replit 想做的是一个足够自然的地方，让人把想法表达出来，而这些想法能“几乎像魔法一样”变成真正的软件，而且不是玩具式的软件，而是能上线、能扩展、能安全运行的真实软件。

主持人随后指出，Replit 很像第一个既是开发工具、又明显不是只卖给工程师的开发工具。Amjad 解释说，这背后和他自己的经历有关。他很小就开始写代码，但自己真正迷恋的从来不是语法本身，而是“创造”这件事，以及创业这件事。相反，他一直觉得开发工具经常在妨碍创造，而且随着时间推移，很多开发工具其实变得更糟了。

他举了自己一路学编程的例子。最开始接触 BASIC 的时候，打开解释器就能直接开始写程序。但等到自己大学毕业，哪怕只是起一个现代 Web App，光是把 React、Webpack 和一堆前端工具链搭起来，过程都已经复杂得令人疲惫。所以他一直有一个很强的念头：能不能把开发工具做得更快乐、更以创造为中心，而不是被一堆偶然复杂性包围。

他后来自己做了很多内部工具，最终慢慢变成了早期浏览器 IDE 这类形态。他还提到自己做过 React 和 React Native 相关工作，而自己每次做开发工具时，都在追一个问题：能不能把消费级应用那种设计感和产品感，带到开发工具里。这个思路后来逐渐演变成 Replit 的长期方向：让编程变得可接近。

Replit 很长一段时间的使命是“创造十亿开发者”。但随着他们不断把软件开发生命周期一层层抹平，团队也逐渐意识到，很多传统开发者其实并不想摆脱那些复杂性。有些人就是喜欢自己搭环境、配每一个细节，那更像工匠对工具的热爱。这本身没有问题，但也让 Replit 更清楚：他们最能帮助的，并不一定是最传统的那批工程师。

Amjad 说，现在真正从产品里拿到最大价值的，常常是更 tech-adjacent 的那群人。比如一些产品经理，很多年前写过一点代码，但不想再被开发环境和部署环境拖住；比如一些设计师，他们明明有具体想法，却总是受制于工程资源；再后来随着 AI 加进来，创业者也越来越多。Amjad 说，当他和这些人聊天时，总会想起过去的自己：他们有想法、有激情、有行动冲动，只是长期被“你得先变成一个技术人”这件事卡住。

于是到 2023 年左右，Replit 内部其实已经把方向说得非常明确：他们不是在优先为传统开发者做工具，而是在为 creators 做产品。公司内部当然还是很多工程师，外表看上去也像一家 dev tools 公司，但真正服务的，是一批新的开发者，一批因为 AI 出现而得以构建软件的人。这批人不需要先搞懂系统里的每个技术组件，依然可以做出可靠的软件。

主持人接着请他讲讲，今天人们到底在 Replit 上做什么。Amjad 把用途分成几类：个人软件、企业软件，以及创业者拿来做新产品。他提到一个自己很喜欢的例子：一个做物理治疗的创业者夫妇。妻子在筋膜和筋膜释放这个细分物理治疗方向上积累了大量深知识，希望做一款很复杂的 app，能扫身体、记录活动范围，还能在 3D 身体模型上跟踪变化。他们之前在全球范围内外包开发，花了几十万美元，但一直被这个过程折腾得很痛苦。后来他们干脆自己在 Replit 上做，结果做出的东西在 Amjad 看来，是他见过最好的健康科技应用之一。

他拿这个例子想说明的，不只是“AI 可以让非程序员也做 App”，而是最接近问题的人终于有机会亲手做产品。主持人马上接了一句：这很关键，因为真正懂领域问题的人，以前常常并不是有权写产品的人。Amjad 完全同意。

他又继续举例。比如有创始人在做泳池维护行业的软件，因为自己家里本来就在做泳池生意，所以对这个市场的问题非常熟。还有人在做体育俱乐部的软件，结果一看他们现在用的系统，居然还是基于 MS-DOS。Amjad 说，在硅谷看世界，很容易觉得“软件好像都做完了”，但实际上还有太多行业、太多生活场景，对很多人来说完全是盲区。一旦更多人都能做软件，经济里大量没被照顾到的地方就会被改善。

他也谈到 personal software。比如家庭医疗、可穿戴数据管理、儿童任务管理等方向，都开始出现普通人自己做的软件。有位韩国母亲甚至做了一套帮助管理孩子罕见病状况的软件；也有人做家庭 chores 排行和激励系统。Replit 在他眼里不只是一个开发环境，而是让更多“最懂问题的人”第一次有机会直接把问题变成软件。

最后他又提到企业场景。在企业里，需求通常落在两类：一类是 product development，希望公司整体发产品更快，因为每个团队都感受到 AI 带来的速度压力；另一类则是内部软件和流程软件的快速搭建。整条访谈前半段的主线因此很明确：Replit 不再只是一个让工程师写代码更方便的工具，而是在重新定义“谁可以做软件”，以及“公司内部谁最应该拥有软件构建能力”。
